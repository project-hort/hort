## Context

`sqlx` (currently 0.8.6) is the relational backbone: `hort-adapters-postgres`
implements every Postgres outbound port on it, and `hort-server`/`hort-worker`
wire its pools. There are **no compile-time `sqlx::query!` macros in the
workspace** (verified — one comment reference only, no `.sqlx/` offline
cache); this is a runtime-API-only migration.

Current workspace pin:
`sqlx = { version = "0.8", features = ["runtime-tokio", "postgres", "uuid", "chrono", "json", "tls-rustls"] }`

## Scope

1. Bump the workspace pin to `0.9`. Verify each feature still exists with the
   same meaning; state the mapping for any rename in the report. If 0.9 forces
   an explicit rustls crypto-backend choice, pick the `aws-lc-rs`-backed
   variant (workspace standard — jsonwebtoken/aws-lc-rs precedent) and flag
   it. Scoped `cargo update`; no unrelated lock drift.
2. Migrate `hort-adapters-postgres` + pool wiring in `hort-server` /
   `hort-worker` to 0.9's runtime APIs.
3. **Error-classification parity (load-bearing deliverable).** Enumerate every
   site where adapter code inspects `sqlx::Error` (or database error codes
   through it) and state per site that classification is identical under 0.9:
   - unique-violation detection on event-store append (idempotency +
     optimistic-concurrency `expected_version` conflict detection — this is
     the event-sourcing security boundary);
   - RETURNING-row shapes / `RowNotFound` handling;
   - timeout / pool-exhaustion classification (task-queue lease paths).
   A silently re-classified error here corrupts event-store invariants
   without failing any compile — that is why this batch is parity-gated.
4. Migration-runner compatibility: `sqlx::migrate!` (or the runner in use)
   accepts the existing `migrations/` tree unchanged — no re-checksum
   surprises, no new validation rejecting existing files.
5. DB-gated suites pass with assertions unmodified; every test keeps its
   `#[serial(hort_pg_db)]` key (the parallel-safety contract in CLAUDE.md is
   untouched).
6. Attribution regen (ADR 0049); `# AUDIT-ONLY` marker re-check
   (`cargo tree -i` per `.cargo/audit.toml` entry).

## STOP condition

If 0.9 changes query/transaction semantics on the event-store append or
optimistic-concurrency path in a way that cannot be shown behavior-identical
mechanically (source diff, error-code tables, targeted tests), STOP and
report — do not adapt the domain/app layer to a changed adapter behavior.
